# Working agreements for agents in this repo

Read `README.md` first, then `docs/adr/` for the "why" behind the build setup.

## Validation hygiene (important)

**Do not run end-to-end or browser validation on your own initiative. Ask the user
first.** That means: no `scripts/e2e.mjs`, no headless Chromium/Playwright/Puppeteer
runs, and no starting a dev server "just to check" the change. The user does that
evaluation and will tell you when they want it.

Static checks (`pnpm typecheck`, `pnpm lint`, `pnpm build`) are fine to run yourself —
they are fast, local and part of `pnpm verify`.

**If a server, browser or other long-lived process is started anyway** — because the
user asked, or a task genuinely requires it — it must be stopped before you finish
and its scratch files deleted. A stray `next dev` on port 8600 will be picked up by
the user's next `pnpm dev`, and stray Chromium instances hold hundreds of MB of RAM
(this app loads ~670 MB of model weights into a worker).

Concretely:

```bash
# start (background)
pnpm dev &                       # or: node scripts/dev.mjs

# ... do the work ...

# stop it, by PID — do NOT use `pkill -f "next dev"`:
#   the pattern matches your own shell command line and kills your session.
ps -eo pid,args | grep -E "next dev|next-server|dev\.mjs" | grep -v grep
kill -TERM <pids...>
```

Then confirm nothing is left behind:

```bash
ss -ltn | grep 8600 || echo "port free"
pgrep -c chromium || echo "no browsers"
rm -rf /tmp/mockbird-e2e* /tmp/diag*.mjs /tmp/smoke*.mjs /tmp/*.log
```

Notes:

- `pgrep`/`pkill` with `-f` match the **full command line**, so a pattern that
  appears anywhere in your own command (including inside the `pkill` invocation
  itself) will match your own shell. Use `[n]ext` style bracket patterns, or
  better, resolve PIDs first and `kill` them.
- Before starting a dev server, check whether one is already listening on 8600 —
  a stale server serves stale code and produces confusing results.
- Scratch output goes under `/tmp/mockbird-*`, never into the repo.
- `scripts/e2e.mjs` is self-cleaning: it kills its browser on exit and writes its
  report to `/tmp/mockbird-e2e/report.json`. If it is aborted with a signal, check
  for a leftover `chromium` process and the `/tmp/mockbird-e2e-profile` directory.

## Interface (do not undo without asking)

- **No sidebar.** One centred glass panel with three tabs — `/` Generate, `/clone`
  Clone, `/settings` Settings — floating over an ambient gradient field.
  `/studio`, `/voices` and `/model` are permanent redirects.
- **Design language is borrowed from `~/shoufa`**: zinc neutrals, inverted primary
  (`text-primary` is near-black on light / near-white on dark), violet `--ring`,
  `--radius: 0.75rem`, and the `.glass-control` / `.apple-panel` / `.ambient-bg`
  utilities. `ThemeProvider` (next-themes) + `ThemeToggle` came from there too.
- **Hide the machinery.** Technical controls (threads, sampling, per-file logs,
  capability report, profiler) live behind `<Details>` disclosures. Casual users
  should only need: download → pick a voice → press a button.
- New surfaces should use `src/components/layout/Panel.tsx` (`Panel` + `Details`).

## Dev environment

- **Always `pnpm`**, never npm/yarn (`packageManager` is pinned).
- Dev server is **HTTPS on port 8600** via mkcert; certificates live in the
  git-ignored `mkcert/` folder (`pnpm certs` regenerates). Plain HTTP only works
  as a secure context on `localhost`, so never suggest `http://<lan-ip>:8600`.
- **Lint and format with Biome** (`pnpm lint`, `pnpm format`). ESLint is not
  installed and must not be reintroduced. `src/components/ui/**`, `vendor/**`,
  `public/**` and `*.css` are excluded on purpose (generated / not Biome-parseable).
- `pnpm verify` = typecheck → lint → build. Run it before declaring work done.
- Dev uses webpack (`next dev --webpack`) because Turbopack's dev server blows the
  RAM budget; production builds with Turbopack. Do not add a `webpack` key to
  `next.config.ts` — dev would use it and `next build` would silently ignore it.
- Never commit `mkcert/`, `public/ort/`, or `public/tokenizer.worker.js`
  (regenerated by postinstall / `pnpm copy:ort` / `pnpm copy:tokenizer`).
- Changes to `src/lib/tts/vendor/mossTtsRuntime.js` must be made as patches in
  `scripts/vendor-patches.json` and re-applied with `pnpm sync:vendor`. A
  hand-edit is lost the next time anyone syncs (this already happened once).
